# Testing documentation

Проект покрыт тестами на нескольких уровнях.

## Запуск

```bash
source .venv/bin/activate
python manage.py test
```

Текущий результат:

```text
Ran 46 tests
OK
```

## Структура тестов

| Файл | Что проверяет |
| --- | --- |
| `social/tests/test_models.py` | constraints, signals, счетчики, валидация моделей |
| `social/tests/test_services.py` | бизнес-логика подписок, приватности, реакций, комментариев, сообщений |
| `social/tests/test_views.py` | HTML routes и простые JSON endpoints |
| `social/tests/test_api.py` | DRF API, token auth, Swagger, posts, users, comments, messages, reports |

## Важные сценарии

Модели:

- профиль создается автоматически;
- нельзя подписаться на себя;
- нельзя дублировать подписку;
- пустой пост невалиден;
- ответ на комментарий должен относиться к той же публикации;
- счетчик реакций синхронизируется сигналами;
- soft-delete комментария уменьшает публичный счетчик комментариев.

Сервисы:

- создание поста нормализует теги;
- приватные публикации скрыты от чужих пользователей;
- followers-only публикации видны активным подписчикам;
- закрытый профиль создает pending-заявку;
- владелец профиля может одобрить заявку;
- блокировка удаляет подписки;
- реакция переключается create/update/delete;
- комментарий создает уведомление;
- закладка переключается idempotent-действием;
- заблокированные пользователи не могут писать друг другу;
- поиск учитывает приватность.

Views:

- аноним видит только публичную ленту;
- авторизованный пользователь создает пост;
- профиль обновляется через HTML-форму;
- подписка создается из профиля;
- заявка закрытого профиля подтверждается;
- комментарий добавляется через страницу публикации;
- уведомления отмечаются прочитанными;
- поиск находит пользователей и посты;
- API feed возвращает JSON.

API:

- регистрация возвращает token;
- login возвращает token;
- `/auth/me/` обновляет вложенный профиль;
- Swagger UI, ReDoc и schema доступны;
- публикация создается через `/api/v1/posts/`;
- лента API учитывает followers-only приватность;
- follow, approve и block работают через user actions;
- reaction, bookmark и comment работают через API;
- уведомления читаются через API;
- direct conversation создает диалог и сообщения;
- жалоба создается через moderation API.

## Почему тесты важны для проекта

Социальная сеть содержит много пересекающихся правил: приватность, блокировки, подписки, авторство, уведомления. Такие правила легко сломать при добавлении API или нового frontend. Тесты фиксируют ожидаемое поведение и показывают, что backend работает не только в одном ручном сценарии, а системно.
